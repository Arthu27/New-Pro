# Данные, обновления и первый запуск бота

Короткая памятка: где живут настройки, почему они не пропадают при
обновлении, и что сделать в первый раз, когда добавляешь бота на сервер.

---

## 1. Где что лежит (и почему не исчезает)

| Что | Где | Обновления трогают? |
|---|---|---|
| Настройки, база, заявки, варны, логи | `data\` (JSON + sqlite) | **Нет** — папка в `.gitignore`, обновлялка её пропускает |
| Токен и секреты | `.env` | **Нет** — тоже в `.gitignore`, пропускается |
| Резервные копии | `backups\` | **Нет** |
| Код бота и панели | `main.py`, `cogs\`, `web\`, … | Да — только его и обновляем |

То есть `git pull` и `update.bat` меняют **только код**. Всё, что вы
настроили в панели и команды, настроил бот — остаётся на месте.

## 2. Как обновляться

**Способ 1 — двойной клик (проще всего):**
`update.bat` → сам скачает свежую сборку с GitHub, положит код поверх
старого (не трогая `data\`, `.env`, логи), поставит зависимости и
перезапустит бота. Без перезапуска: `update.bat /norestart`.

**Способ 2 — если папка бота — клон с GitHub:**
```
git pull
```
и перезапустить бота (`start_bot.bat`).

> Обновлялка качает **последний релиз** репозитория по постоянной
> ссылке — она НЕ меняется, от какой ветки ни была бы сборка. Ветка
> прописанная в `update.bat`, — только запасной путь, пока релизов нет.
> Поэтому обновлялку не нужно править при каждом обновлении.
>
> Если на сервере старая обновлялка ругается «SSL/TLS secure channel» —
> скачайте свежий `update.bat` по постоянной ссылке (тег релиза — адрес
> не меняется никогда) и замените старый файл (один раз), дальше снова
> всё в один клик:
> https://github.com/Arthu27/New-Pro/raw/latest/update.bat

## 3. Резервные копии (подстраховка)

- **Автоматически:** раз в день бот сам делает zip всей `data\` и держит
  последние 7 копий (старые подрезает). Час и количество — в `.env`
  (`BACKUP_HOUR`, `BACKUP_KEEP`), включение — `BACKUP_ENABLED`.
- **Вручную в Discord:** `/backup now` — сделать копию прямо сейчас,
  `/backup list` — список копий (обе — только для админов).
- **В панели:** страница «Резервные копии» — те же архивы, скачиваются
  кнопкой.

Чтобы развернуть копию: остановить бота, распаковать zip в `data\`,
запустить бота.

## 4. Первый запуск: добавить бота на сервер

1. **Создать приложение:** [discord.com/developers/applications](https://discord.com/developers/applications)
   → New Application → вкладка **Bot** → Reset Token → скопировать токен.
2. **Включить интенты** (вкладка Bot, раздел Privileged Gateway Intents):
   - Presence Intent — вкл
   - Server Members Intent — вкл
   - Message Content Intent — вкл

   Бот использует все три — без них часть функций молча не работает.
3. **Токен — в `.env`** (файл рядом с `main.py`; образец — `.env.example`):
   ```
   TOKEN=вставить_токен
   OWNER_ID=твой_discord_id
   MAIN_GUILD_ID=id_сервера
   PANEL_USER=admin
   PANEL_PASSWORD=надёжный_пароль
   ```
4. **Пригласить бота:** вкладка OAuth2 → URL Generator → scopes `bot`,
   permissions — Administrator (свой сервер, проще всего) → открыть
   сгенерированную ссылку → выбрать сервер.
5. **Проверить роль бота:** в настройках сервера роль бота должна стоять
   **выше** ролей «Хелпер» и «Модератор» — иначе бот не сможет выдавать их
   после одобрения заявок.
6. **Запустить:** `start_bot.bat` (бот) и `start_panel.bat` (панель).
   Панель: http://localhost:5001 (на VPS — через ваш домен).

## 5. Если сервер не ваш (вы не основатель)

Всё работает — владелец панели определяется не основателем сервера, а
владельцем бота:

- В `.env` укажите `MAIN_GUILD_ID=id_того_сервера` — панель будет
  управлять **только им**: все настройки и данные привязаны к этому
  серверу. Даже если бота позже добавят на другие серверы, панель не
  переключится и чужие данные через неё недоступны.
- В `.env` укажите `OWNER_ID=свой_discord_id` — панель даст вам роль
  «Владелец» (все разделы, включая «Доступ»). Основатель сервера тоже
  получает «Владельца» автоматически.
- Хотите дать полный доступ ещё кому-то — впишите его ID через запятую:
  `OWNER_IDS=123456789,987654321`. Каждому из них нужна своя учётка
  панели (логин/пароль), ID лишь поднимает роль до «Владельца».
- Владельцам бота (OWNER_ID + OWNER_IDS) бот **ничего не проверяет**:
  команды не режутся правилами ролей, лимиты наказаний и обязательные
  доказательства не спрашиваются. Ограничения — для остальной команды.
- «Обязательные доказательства к наказаниям» теперь по умолчанию
  **выключены**. Включить, когда понадобится: панель → «Доказательства».
- На самом сервере попросите основателя дать **вам** роль с правами
  администратора — без неё не пустит часть slash-команд настройки
  (`/staff-panel`, тикеты и т.п.).
- Роль **бота** основатель должен поставить **выше** ролей «Хелпер» и
  «Модератор» (иначе бот не сможет их выдавать после одобрения заявок).
- Бот не сможет наказывать основателя и менять ему ник (правило Discord
  о старшинстве ролей — так у всех ботов). Проверки прав в боте честно
  предупредят, если чего-то не хватит.

## 6. Первые шаги после запуска

- Войти в панель, проверить разделы «Доступ» и «Команды».
- `/staff-panel` — панель набора в команду (Хелпер / Модератор); после
  одобрения заявки бот сам выдаёт роль (ищет по имени «Хелпер»/«Модератор»
  на сервере; можно задать ID в `.env`: `STAFF_HELPER_ROLE_ID`,
  `STAFF_MODERATOR_ROLE_ID`).
- Ветки заявок: хелперы и модераторы — в РАЗНЫЕ каналы, куратор один на обе.
  Проще задать в панели (см. раздел ниже); запасной путь — `.env`:
  `STAFF_HELPER_CHANNEL_ID` / `STAFF_MODERATOR_CHANNEL_ID` (каналы) и
  `STAFF_CURATOR_ROLE_ID` (какую роль пинговать в ветках).
  Не заданы — общий `APPLY_CHANNEL_ID`.
- Проверить, что авто-бэкап включён: `/backup list` покажет расписание,
  первый архив появится в течение суток.

## Заявки в команде — настраивается в панели

- **«Настройки» → «Каналы и маршруты»**: ветка заявок хелперов, ветка модераторов,
  общий канал заявок — селекторы каналов.
- **«Настройки» → «Бот»**: роль хелпера и роль модератора (выдаются после одобрения)
  + **куратор заявок — один на обе ветки** (роль, которую бот пингует в ветках).
- Решение по заявке в Discord — select «Принять / Отклонить» (старые сообщения
  с кнопками тоже остаются рабочими).

Порядок: настройка из панели → переменные `STAFF_*` в `.env` → автопоиск роли
по имени («Хелпер», «Модератор»). Значение «Авто» в селекторе = `.env`/автопоиск.
Хранение: `data/staff_apply_settings.json` (не трогается обновлялкой). Раньше
кураторов было два (STAFF_*_CURATOR_ROLE_ID) — теперь один `STAFF_CURATOR_ROLE_ID`,
старые переменные/настройки работают как запасное значение.
