# Данные, обновления и первый запуск бота

Короткая памятка: где живут настройки, почему они не пропадают при
обновлении, и что сделать в первый раз, когда добавляешь бота на сервер.

---

## 1. Где что лежит (и почему не исчезает)

| Что | Где | Обновления трогают? |
|---|---|---|
| Настройки, база, заявки, варны, логи | `data\` (JSON + sqlite) | **Нет** — папка в `.gitignore`, обновлялка её пропускает |
| Токен и секреты | `.env` | **Нет** — тоже в `.gitignore`, пропускается |
| Резервные копии | `backups\` | **Нет** |
| Код бота и панели | `main.py`, `cogs\`, `web\`, … | Да — только его и обновляем |

То есть `git pull` и `update.bat` меняют **только код**. Всё, что вы
настроили в панели и команды, настроил бот — остаётся на месте.

## 2. Как обновляться

**Способ 1 — двойной клик (проще всего):**
`update.bat` → сам скачает свежую сборку с GitHub, положит код поверх
старого (не трогая `data\`, `.env`, логи), поставит зависимости и
перезапустит бота. Без перезапуска: `update.bat /norestart`.

**Способ 2 — если папка бота — клон с GitHub:**
```
git pull
```
и перезапустить бота (`start_bot.bat`).

> Ветка сборки прописана внутри `update.bat`. Если обновлялка качает не
> ту ветку или ругается «SSL/TLS secure channel» — скачайте свежий
> `update.bat` в браузере и замените старый файл (разовая ручная замена,
> дальше снова один клик):
> https://github.com/Arthu27/New-Pro/raw/arena/01a03640-new-pro/update.bat
>
> «SSL/TLS» на старых Windows Server — старый PowerShell не умеет TLS 1.2;
> свежая версия обновлялки обходит это через curl.exe.

## 3. Резервные копии (подстраховка)

- **Автоматически:** раз в день бот сам делает zip всей `data\` и держит
  последние 7 копий (старые подрезает). Час и количество — в `.env`
  (`BACKUP_HOUR`, `BACKUP_KEEP`), включение — `BACKUP_ENABLED`.
- **Вручную в Discord:** `/backup now` — сделать копию прямо сейчас,
  `/backup list` — список копий (обе — только для админов).
- **В панели:** страница «Резервные копии» — те же архивы, скачиваются
  кнопкой.

Чтобы развернуть копию: остановить бота, распаковать zip в `data\`,
запустить бота.

## 4. Первый запуск: добавить бота на сервер

1. **Создать приложение:** [discord.com/developers/applications](https://discord.com/developers/applications)
   → New Application → вкладка **Bot** → Reset Token → скопировать токен.
2. **Включить интенты** (вкладка Bot, раздел Privileged Gateway Intents):
   - Presence Intent — вкл
   - Server Members Intent — вкл
   - Message Content Intent — вкл

   Бот использует все три — без них часть функций молча не работает.
3. **Токен — в `.env`** (файл рядом с `main.py`; образец — `.env.example`):
   ```
   TOKEN=вставить_токен
   OWNER_ID=твой_discord_id
   MAIN_GUILD_ID=id_сервера
   PANEL_USER=admin
   PANEL_PASSWORD=надёжный_пароль
   ```
4. **Пригласить бота:** вкладка OAuth2 → URL Generator → scopes `bot`,
   permissions — Administrator (свой сервер, проще всего) → открыть
   сгенерированную ссылку → выбрать сервер.
5. **Проверить роль бота:** в настройках сервера роль бота должна стоять
   **выше** ролей «Хелпер» и «Модератор» — иначе бот не сможет выдавать их
   после одобрения заявок.
6. **Запустить:** `start_bot.bat` (бот) и `start_panel.bat` (панель).
   Панель: http://localhost:5001 (на VPS — через ваш домен).

## 5. Первые шаги после запуска

- Войти в панель, проверить разделы «Доступ» и «Команды».
- `/staff-panel` — панель набора в команду (Хелпер / Модератор); после
  одобрения заявки бот сам выдаёт роль (ищет по имени «Хелпер»/«Модератор»
  на сервере; можно задать ID в `.env`: `STAFF_HELPER_ROLE_ID`,
  `STAFF_MODERATOR_ROLE_ID`).
- Проверить, что авто-бэкап включён: `/backup list` покажет расписание,
  первый архив появится в течение суток.
