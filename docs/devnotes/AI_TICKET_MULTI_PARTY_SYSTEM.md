# Система AI-тикетов — Многосторонняя система наказаний

## Обзор

Классический сценарий «жалоба на одного нарушителя» не работает,
когда в конфликте участвуют обе стороны (взаимные оскорбления,
провокации). Эта система учит AI анализировать **всех участников**
инцидента и распределять ответственность справедливо.

## Новые возможности

### 1. Определение взаимных нарушений
AI проверяет диалог/скриншоты не только на «вину заявителя»,
но и на провокации, оскорбления и нарушения с обеих сторон.

### 2. Анализ удалённых сообщений
Сообщения, которые стороны успели удалить, подтягиваются из кэша
бота (пока сообщение попало в кэш до удаления) и учитываются
в разборе — «почистить переписку» больше не помогает.

### 3. Справедливое распределение наказаний
Наказание назначается пропорционально вкладу каждой стороны,
а не по принципу «кто первый пожаловался — того и победа».

## Матрица решений

| Ситуация | Заявитель | Ответчик | Решение |
|---|---|---|---|
| Односторонняя атака | без нарушений | оскорбления | Наказание ответчику |
| Взаимный конфликт | провокация | оскорбления | Оба: ответчику строже |
| Провокация заявителя | начал конфликт | ответил грубо | Оба: лёгкие меры / предупреждения |
| Ложная жалоба | подтасовка | без нарушений | Меры к заявителю, снятие подозрений |

## Технические детали

### Обновление AI-промпта
В системный промпт разбора жалобы добавлены обязательные проверки:

```
ПРОВЕРЬ:
1. Есть ли нарушения у ОБЕИХ сторон?
2. Не смоделирована ли ситуация (провокация ради жалобы)?
3. Есть ли удалённые сообщения от любой из сторон?

КРИТИЧЕСКИЕ ПРАВИЛА:
- Никогда не предлагай наказывать только одну сторону
  при доказанной обоюдности.
- Указывай вину каждой стороны в процентах.
- Ложная жалоба = нарушение само по себе.
```

### Новые типы решений
- `mutual_violation` — обоюдное нарушение
- `provocation` — спровоцированный конфликт
- `false_report` — ложная/подтасованная жалоба
- `single_offense` — классическое одностороннее нарушение

### Изменения кода
- `cogs/ticket.py` — расширен разбор жалоб
- `services/advanced_ticket_features.py` — типы решений, штрафы,
  распределение наказаний
- `data/ticket_penalties.json` — учёт многосторонних инцидентов

## Сценарии использования

1. **Оба виноваты** → мут обоим, срок пропорционален тяжести вклада.
2. **Апелляция после обоюдного мута** → пересмотр с учётом матрицы.
3. **Ложная жалоба** → отклонение + отметка в истории заявителя.
