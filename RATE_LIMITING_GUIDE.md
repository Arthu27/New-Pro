# 🛡️ Система Rate Limiting — Тикеты

## Общий обзор

Защита тикет-системы от злоупотреблений: флуд открытием тикетов,
спам сообщениями внутри тикета и нагрузка на AI-API
(каждый ответ AI = платный запрос к провайдеру).

## 📦 Файлы

- `services/rate_limiter.py` — ядро ограничений (окна, счётчики, блокировки).
- `cogs/ticket.py` — применение лимитов при открытии и в диалоге тикета.
- `web/routes_extra.py` — эндпоинты панели (статус лимитов, разблокировка).

## 🔧 Функции

### Защита
- **Лимит открытия тикетов** — максимум N тикетов за период на пользователя.
- **Лимит сообщений AI** — ограничение числа AI-ответов на тикет/на пользователя
  в единицу времени (защита бюджета AI-API).
- **Кулдаун после закрытия** — пауза перед следующим открытием.
- **Авто-блокировка** — при серии нарушений пользователь временно
  не может открывать тикеты.

### Технические функции
- Скользящее окно (sliding window) по пользователю и по серверу.
- Глобальный лимит AI-вызовов — под защитой весь сервер при атаке.
- Счётчики в памяти + сброс по истечении окна; не привязаны к кэшу Discord.
- Мягкое уведомление пользователю («подождите N сек.») вместо молчаливого отказа.

## 🚀 Использование

### Автоматически (при открытии тикета)
Работает из коробки: при превышении лимита пользователь получает
сообщение с таймером ожидания, тикет не создаётся.

### Команды администратора
- Просмотр статуса лимитов и заблокированных пользователей — веб-панель,
  раздел тикетов.
- Ручная разблокировка пользователя — там же, либо командой модерации.

## ⚙️ Конфигурация

Значения по умолчанию задаются в `services/rate_limiter.py`
(окна, пороги, длительность блокировки). Рекомендуется менять только
после замера фактической нагрузки на AI-API.

> ⚠️ Слишком жёсткие лимиты мешают реальным пользователям;
> слишком мягкие — не защищают бюджет AI-API.
> Начните с дефолтных и наблюдайте статистику эскалаций.
